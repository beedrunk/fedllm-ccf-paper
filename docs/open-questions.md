# 仍需确认的问题

这些是当前计划中的盲点。每解决一个，就更新本文件。

## 算力真实性

用户描述为 4060，显存 32 GB。常见 RTX 4060 显存配置通常不是 32 GB，因此需要用 `nvidia-smi` 核验：

- GPU 型号。
- 显存容量。
- CUDA 版本。
- 驱动版本。

影响：
- 如果显存不是 32 GB，模型可能需要降到 0.5B 或更小。
- 如果训练速度过慢，主实验要减少客户端数和随机种子。
- 后期可租用服务器，因此本地 GPU 主要影响前期开发和最小可行实验，不必决定最终投稿实验上限。

当前状态：
- 2026-05-25 在项目环境中直接运行 `nvidia-smi` 失败。
- 常见路径 `C:\Windows\System32\nvidia-smi.exe` 和 `C:\Program Files\NVIDIA Corporation\NVSMI\nvidia-smi.exe` 未找到。
- 第一周必须先确认 NVIDIA 驱动、CUDA 和 PyTorch GPU 可用性。

## 教育数据集

用户希望英文教育方向，但公开教育数据集未必适合 LoRA 指令微调和联邦划分。

需要确认：
- 是否必须教育场景作为主实验。
- 是否接受通用 NLP 数据集作为主实验，教育数据作为补充实验。
- 数据集许可证是否允许科研使用和开源配置。

## 目标期刊

目标是 CCF C 英文期刊，但不能凭记忆写死。

需要确认：
- 当前 CCF 推荐目录版本。
- 候选期刊是否仍为 CCF C。
- 期刊是否接受 FedLLM/ML/NLP 方向。
- 审稿周期是否适合 3 个月投稿计划。

## 代码基础

当前没有 FedLLM 代码基础。

风险：
- 从零实现完整框架会挤压实验和写作时间。

应对：
- 优先复用 Hugging Face Transformers、PEFT 和一个轻量模拟联邦训练循环。
- 暂不引入复杂联邦框架，除非代码复用收益明确。

## 主贡献边界

当前主线是资源异构 + 个性化 FedLoRA。

需要避免：
- 同时声称解决隐私、资源异构、任务异构、通信压缩和个性化。
- 把隐私作为主贡献但没有完整 DP 会计和攻击实验。
